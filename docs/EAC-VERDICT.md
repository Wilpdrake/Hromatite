# EAC: почему «вырезать» нельзя и что реально достижимо (2026-11-18)

Итог трёх независимых разведок и одного живого прогона. Всё, что ниже, —
измерено; гипотезы помечены явно. Детали: `docs/EAC-ADMISSION.md`,
`docs/EAC-RECORDS.md`, `docs/EAC-CUT-CODE.md`, журнал `AGENTS.md` §17.

## 1. Короткий ответ

Полностью убрать EAC из сессии **нельзя** — ни заменой, ни реплеем, ни
подделкой допуска. Античит остаётся единственным производителем валидных
отчётов, и это не недостаток нашей реализации, а свойство протокола.

При этом **для нашей задачи EAC и не нужно вырезать**: его взгляд на процесс
структурно не включает наш payload. Реальная граница — целостность файлов игры,
а не память.

## 2. Что измерено (срок жизни сессии после вмешательства)

| конфигурация | исход | источник |
|---|---|---|
| «полностью без EAC» (стаб бутстрапа) | offline mode, `Error World`, 0 вызовов AC API | `findings/eac_off.md` |
| null-клиент (`EOS_USE_ANTICHEATCLIENTNULL=1`) | вход в мир, кик **~3 с**, далее 24–27 с | там же |
| тишина (drop исходящих кадров) | **120.5 с**, `code 104` | `findings/cut_test.md` |
| forge из шаблона (CRC ок) | **39–75 с** | `findings/forge_test.md` |
| реплей целого чужого отчёта | **51–65 с** | `findings/replay_report_test.md` |
| реплей целого своего сообщения (self-replay) | **193 с** | `docs/EAC-REPLACE-PLAN.md` §8 |
| живая сессия с модулем | без ограничений (283 с, 6+ мин, сегодня 17+ мин) | `evidence/control_0009`, прогон 2026-11-18 |

Чем «честнее» подделка, тем дольше живёт — но ни одна не дотягивает до
бесконечности. Это и есть граница возможного.

## 3. Три причины, каждая доказана отдельно

### 3.1 Допуск подделывается, но это бесполезно

`FAntiCheatClient::Init` (`0x1803BAA70`) зовёт слот `+0xE8` (`0x1803BE4D0`); там
`mov ecx,0xE08` → `call 0x180B11C20`, а тот через IAT `0x180E73220` вызывает
**`GetProcAddress`**. NULL ⇒ `0x1803BEEEB` ⇒ `mov eax,0x2ee0` (**12000,
ClientProtectionNotAvailable**) ⇒ ветка «клиента нет» / «null client».
Имя в вызове — пустая wide-строка; в EOSSDK **ноль** строк `EasyAntiCheat` —
named-секций, событий и файлов-маркеров не существует.

Подделать «есть» можно патчем `GetProcAddress`, но SDK сразу пойдёт по
`jmp [client+0x200]`, а `+0x200` заполняется только в null-ветке ⇒ падение.
Даже если обойти — отчётов не будет, и сессия умрёт по §2.

### 3.2 Записи отчёта непроизводимы

2533 кадра / 496 сообщений / 55 741 запись (2026-11-18):

* две сессии **одного процесса** — 0 совпадений записей на тех же позициях;
* 33 277 071 конструкция хешей (BLAKE3 plain/salted/keyed, MD5, SHA-1/2/3,
  BLAKE2, усечения и XOR половин) над всеми файлами установки и страницами
  512…65 536 Б — **0 совпадений**;
* запись не встречается как подстрока ни в `base.bin`, ни в образе модуля, ни
  в `stage1_module.so`;
* внутри записи нет счётчика, времени или адреса (χ²=221.2 при df=255; доля
  единичных бит 0.49968);
* в модуле BLAKE3-256 вызывается 4 раза, ни одного `finalize(…,16)` — форма
  записи (32→16) достижима только через vtable.

Следствие: свежие записи умеет делать только модуль.

### 3.3 «Протухание» за 193 с — это не порча записей, а отсутствие ack

В захвате видно: отчёт `counter=267` ушёл кадрами `seq 144…147`, затем
`145/146/147` повторялись 30/29/29 раз, Σdt = 184 941 мс, завершающего кадра
нет. 184.9 с ≈ измеренным 193 с. То есть сервер перестаёт подтверждать, и
сессия умирает по своему лизингу (39…211 с в разных режимах), а не потому, что
мы «отправили устаревшие байты».

## 4. Что реально достижимо (и уже достигнуто)

| уровень | состояние |
|---|---|
| **транспорт под нашим контролем** — 8 хуков EOSSDK, capture, drop, replay, инварианты | ✅ живьём (512 Б / ~2007 мс, 170 кадров за прогон) |
| **эмиттер не шлёт кадры мёртвой эпохи** (`epoch::Gate`) | ✅ код + host-тесты; живой прогон в observe, takeover не включали |
| **чтение образа античита из payload** | ✅ живьём: `0x7c4eb05a1000`, span `0x65f000`, 5 LOAD, `ET_DYN`, поля совпадают с офлайн-дампом |
| **подавление локальных вердиктов** (`EAC_BLIND`) | ⚠️ код есть, но игра **не вызывает** `AddNotifyClientIntegrityViolated` / `GetModuleBuildId` / `GetSystemRequirementStatus` (0 вызовов) — подавлять нечего |
| **запись/патч образа модуля** | ❌ не проверено: нужен `mprotect` сырым `syscall` из PE; WinAPI этот регион не видит |

### Как payload вообще видит модуль (две ловушки, обе измерены)

1. `VirtualQuery` показывает только маппинги, созданные Wine: образ модуля для
   него «unmapped», хотя прямое чтение по адресу работает.
2. `\\?\unix\proc\self\maps` открывает **wineserver**, поэтому `self` — это он
   (111 маппингов против 2472 у игры).

Рабочий путь: `/proc/<pid>/cmdline` → pid → `/proc/<pid>/maps` → memfd-база →
таблица «файловое смещение → адрес» из сегментов (последний LOAD:
`p_offset 0x219000`, `p_vaddr 0x222000`) → чтение под VEH в границах сегментов.
Реализация — `crates/hromatite-eac/src/eacimage.rs`, команда `eac.module`.

## 5. Что это значит для безопасности проекта

* **Детект нашего payload структурно невозможен с linux-стороны**: модуль
  перечисляет только ELF через `link_map`, PE-образы туда не попадают, плюс
  `peb unlink: true` и стёртые заголовки. `Forbidden module` не приходил ни в
  одном прогоне — и не может.
* **Реальный риск — целостность файлов игры**, а не память: правка файлов в
  prefix при живом EAC ловится как `failed to verify installation integrity`
  (error 16). Отсюда правило: доставка только через launch options, файлы игры
  не трогаем.
* **EAC Linux v2** (`eBPF`+LSM, без драйвера) запретит чтение/запись чужой
  памяти с хоста; на NixOS аттестация, скорее всего, не пройдёт — риск не
  «нас поймают», а «игра перестанет запускаться». Это отдельный трек.

## 6. Если всё-таки идти в «ослепление»

Единственный оставшийся путь — заставить модуль генерировать чистые отчёты,
то есть вмешаться в его собственные чтения. Для этого нужно:

1. `mprotect` через сырой `syscall` (единственный способ изменить защиту
   native-региона из PE) — проверить на безобидной странице;
2. найти в модуле функцию, собирающую записи (в Ghidra `/11.18` есть
   `FUN_001566e6`, `FUN_0015425c`, `FUN_00154406`, `FUN_0012de28`), и понять,
   что именно она читает;
3. подменить вход функции или её результат — но только после того, как п.1
   доказан: без записи в память этот трек не начинается.

Оценка: это работа уровня «недели», с реальным риском уронить игру патчем в
чужой код. Ценность — только если понадобится обходить будущий детект, которого
сейчас нет.

## 7. Открытые вопросы

* Хеширует ли модуль **нашу** память вообще — не доказано ни в одну сторону;
  известно лишь, что в записях нет ни адресов, ни времени, а каталог `base.bin`
  содержит 32-байтные дайджесты на чанк.
* Чем сервер отвергает реплей: дубликаты тел или собственный лизинг — нужен
  прогон с логированием входящих ack (не делали).
* Три лишних хука (`AddNotifyClientIntegrityViolated`, `GetModuleBuildId`,
  `GetSystemRequirementStatus`) не вызываются — их стоит снять (11→8) и
  перепроверить живым прогоном.
